# Documentation

1. Use concise, precise technical language.
2. Keep introductions brief and state only the topic; explain concepts and details in their respective sections.
3. Include details needed for the reader's decisions and tasks; omit internal behavior unless it is part of a required usage or implementation contract.
4. Write parallel points as concise list items rather than combining them in prose.
5. Begin each guidance document with one short sentence stating its scope.
6. Keep agent guidance focused on durable project knowledge and design decisions; retain concise navigation aids, but condense explanations recoverable from code.
7. Describe responsibilities by purpose rather than exhaustive feature lists so routine additions do not invalidate the guidance.
8. Put cross-component relationships in architecture guidance and component-specific details in their respective documents.
